## 摘要 (Executive Summary)

本篇架构决策记录（ADR）针对 `pi-cordis` 原有预设体系中存在的**过度设计（Over-Engineering）与技术排列组合繁杂问题**进行了深刻反思，确立了回归 Pi 核心灵魂的 **“极简设计哲学（Minimalist Philosophy）” 与 “默认即最佳（Default is Best）” 准则**。

本决策废除了基于“内部插件微小差异”人工堆砌的 5 大混乱预设（`default`, `safe`, `strict`, `full`, `minimal`），收敛为 **3 个具有根本行为形态差异的场景级预设（Default 标准编码 / Plan 规划审计 / PTC 编程调用）**，彻底消除了用户的心智负担。

---

## 一、直面问题：原有预设体系的“繁杂”根源反思

在之前的设计中，过度关注内部插件的技术组合导致陷入了**“面向实现排列组合”**的误区：

```text
【原有混乱体系的 4 大硬伤】
1. safe 与 full 高度重合 : 两个预设均开启了全部 4 个插件，语义混淆，用户无法分辨；
2. default 凭空阉割安全防线 : 默认模式居然不带 safety-gate，日常开发失去防 rm -rf / 保护；
3. strict 随意裁剪辅助工具 : 只读审计模式莫名剔除了 todo-tracker；
4. 4 个插件强行拼凑 5 个预设 : 沦为内部插件开关的排列组合，缺乏真正的业务角色定位。
```

---

## 二、Pi-Cordis 极简设计哲学两大核心准则

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Pi-Cordis 极简设计哲学                          │
├────────────────────────────────────────────────────────────────────────┤
│ 准则一：Default is Best (默认即最佳)                                   │
│ • 开箱即用，默认模式必须是最安全、最完善、体验最好的完整形态            │
│ • 用户启动 pnpm pi 无需做任何配置，安全守门与辅助工具全量就绪           │
├────────────────────────────────────────────────────────────────────────┤
│ 准则二：预设代表“工作形态差异”，而非“内部插件开关”                     │
│ • 预设 (Preset) 绝不是微小功能开关的集合                              │
│ • 每一个预设必须代表智能体在认知、权限和交互上的根本形态改变 (Agent Mode)│
└────────────────────────────────────────────────────────────────────────┘
```

---

## 三、精简重构落地：从 5 大排列组合收敛至 3 大场景预设

我们废除了无意义的技术排列组合，收敛为 **3 个语义极其明确的场景模式**：

```text
【重构前 (5个技术排列组合)】                     【重构后 (3个极简场景预设)】
  ├── default (无安全拦截？)    ───┐
  ├── safe (4个插件全开)        ────┼───> 🌟 1. default (标准编码模式: 开箱即用，安全/规则/待办全开)
  ├── full (4个插件，和safe重复) ───┘
  ├── strict (无todo的只读？)   ────────> 🛡️ 2. plan / review (只读规划模式: 需求拆解与架构探索，严禁写操作)
  └── minimal (为了凑数？)       ────────> ⚡ 3. ptc / code (编程调用模式: TypeScript 批量程序化调用)
```

---

### 1. 🌟 `default` (标准编码模式)
- **定位**：**默认即最佳 (Default is Best)**。适用于 95% 以上的日常 AI 辅助研发工作；
- **能力矩阵**：
  - 危险 Shell 命令与敏感文件拦截 (`safety-gate`)；
  - 项目规范与上下文指南自动发现注入 (`rules-injector`)；
  - 任务待办实时追踪与管理 (`todo-tracker`)；
  - 脏仓库状态校验与自动 Checkpoint 快照恢复 (`git-guard`)。
- **使用交互**：直接运行 `pnpm pi`，无需任何附加参数，开箱即享受最强能力与最高安全防线。

---

### 2. 🛡️ `plan` (只读规划与审计模式)
- **定位**：专用于大型重构、架构探索、需求拆解与安全审计的**只读沙箱模式**；
- **能力矩阵**：
  - 强制开启严格只读保护（`safety-gate: { readOnly: true }`），拦截一切写文件、删文件与破坏性 Bash 执行；
  - 任务规划拆解与只读代码库探索；
  - 保留待办追踪与规则注入。
- **使用交互**：在 TUI 中输入 `/profile plan` 或 CLI 启动 `pnpm pi --profile plan`。

---

### 3. ⚡ `ptc` (编程调用与极速批量执行模式)
- **定位**：专用于海量文件扫描、批量文本替换与复杂数据过滤的**程序化调用模式**；
- **能力矩阵**：
  - 继承 `default` 模式的全部安全与治理能力；
  - 通过 `@pi-cordis/plugin-code-mode` 暴露 TypeScript 强类型 SDK，模型可在一个轮次内完成 5~10 轮交互的复合任务。
- **使用交互**：在 TUI 中输入 `/profile ptc` 或 CLI 启动 `pnpm pi --profile ptc`。

---

## 四、重构收益与架构价值

1. **心智负担彻底清零**：彻底消除用户在 `safe`, `full`, `default` 之间无所适从的选择困难；
2. **安全防线全量对齐**：彻底修复了原有 `default` 裸跑无安全拦截的严重安全隐患；
3. **架构纯粹性回归**：不再将内部插件的技术排列暴露给用户，让 Pi-Cordis 重新拥有轻量、优雅且强大的灵魂。
