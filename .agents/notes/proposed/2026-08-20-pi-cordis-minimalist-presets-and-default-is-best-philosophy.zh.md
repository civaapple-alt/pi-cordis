# Agent Note: Pi-Cordis 极简设计哲学与 “Default is Best” 预设体系重构提案

## 摘要 (Executive Summary)

本篇架构提案（ADR Proposal）针对 `pi-cordis` 当前预设体系中存在的**过度设计（Over-Engineering）与技术排列组合繁杂问题**进行了深刻反思，确立了回归 Pi 核心灵魂的 **“极简设计哲学（Minimalist Philosophy）” 与 “默认即最佳（Default is Best）” 准则**。

本提案主张废除基于“内部插件微小差异”人工堆砌的 5 大混乱预设（`default`, `safe`, `strict`, `full`, `minimal`），收敛为 **2~3 个具有根本行为形态差异的场景级预设（Default 标准编码 / Plan 规划审计 / PTC 编程调用）**，彻底消除用户的心智负担。

---

## 一、直面问题：现有预设体系的“繁杂”根源反思

在之前的设计中，我们由于过度关注内部插件的技术组合，陷入了**“面向实现排列组合”**的误区：

```text
【现有混乱体系的 4 大硬伤】
1. safe 与 full 高度重合 : 两个预设均开启了全部 4 个插件，语义混淆，用户无法分辨；
2. default 凭空阉割安全防线 : 默认模式居然不带 safety-gate，日常开发失去防 rm -rf / 保护；
3. strict 随意裁剪辅助工具 : 只读审计模式莫名剔除了 todo-tracker；
4. 4 个插件强行拼凑 5 个预设 : 沦为内部插件开关的排列组合，缺乏真正的业务角色定位。
```

---

## 二、Pi-Cordis 极简设计哲学两大核心准则

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Pi-Cordis 极简设计哲学                          │
├────────────────────────────────────────────────────────────────────────┤
│ 准则一：Default is Best (默认即最佳)                                   │
│ • 开箱即用，默认模式必须是最安全、最完善、体验最好的完整形态            │
│ • 用户启动 pnpm pi 无需做任何配置，安全守门与辅助工具全量就绪           │
├────────────────────────────────────────────────────────────────────────┤
│ 准则二：预设代表“工作形态差异”，而非“内部插件开关”                     │
│ • 预设 (Preset) 绝不是微小功能开关的集合                              │
│ • 每一个预设必须代表智能体在认知、权限和交互上的根本形态改变 (Agent Mode)│
└────────────────────────────────────────────────────────────────────────┘
```

---

## 三、精简重构方案：从 5 大排列组合收敛至 3 大场景预设

我们将废除无意义的技术排列组合，收敛为 **3 个语义极其明确的场景模式**：

```text
【重构前 (5个技术排列组合)】                     【重构后 (3个极简场景预设)】
  ├── default (无安全拦截？)    ───┐
  ├── safe (4个插件全开)        ────┼───> 🌟 1. default (标准编码模式: 开箱即用，安全/规则/待办全开)
  ├── full (4个插件，和safe重复) ───┘
  ├── strict (无todo的只读？)   ────────> 🛡️ 2. plan / review (只读规划模式: 需求拆解与架构探索，严禁写操作)
  └── minimal (为了凑数？)       ────────> ⚡ 3. ptc / code (编程调用模式: TypeScript 批量程序化调用)
```

---

### 1. 🌟 `default`（标准日常编码模式 / Default Mode）
- **核心定位**：**默认即最佳（Default is Best）**。95% 日常编码的默认选择；
- **能力矩阵**：
  - 高危破坏性命令与保护文件拦截（`safety-gate`）；
  - 项目规则与规范自动扫描注入（`rules-injector`）；
  - 任务清单与待办追踪闭环（`todo-tracker`）；
  - Git 工作区脏状态提示与关键检查点（`git-guard`）。
- **用户体验**：直接运行 `pnpm pi`，无需任何参数，享受最完善的智能体辅助与安全保障。

---

### 2. 🛡️ `plan`（只读规划与审计模式 / Planning & Review Mode）
- **核心定位**：专用于复杂重构、架构探索与方案设计的**只读安全模式**；
- **能力矩阵**：
  - 严格只读模式（`safety-gate: { readOnly: true }`），阻断所有写文件、删文件与执行非查询命令的操作；
  - 规划步骤跟踪与只读探索工具；
  - 待办追踪与规则注入保持生效。
- **切换方式**：在 TUI 中输入 `/profile plan` 或 CLI 启动 `pnpm pi --profile plan`。

---

### 3. ⚡ `ptc`（编程化工具调用模式 / Programmatic Tool Calling Mode）
- **核心定位**：专用于批量数据处理与长链路复杂操作的**程序化执行模式**；
- **能力矩阵**：
  - 继承 `default` 的全部安全与辅助底座；
  - 通过 `@pi-cordis/plugin-code-mode` 将工具呈现为 TypeScript SDK，支持模型编写 TypeScript 脚本将 5~10 轮交互坍缩为 1 轮本地执行。
- **切换方式**：在 TUI 中输入 `/profile ptc` 或 CLI 启动 `pnpm pi --profile ptc`。

---

## 四、重构收益与价值总结

1. **认知负担归零**：用户不再需要在 `safe`、`full`、`default` 之间纠结“谁多了什么、谁少了什么”；
2. **安全无死角**：彻底消除了旧版 `default` 模式因未加载 `safety-gate` 导致的安全裸奔隐患；
3. **架构清爽纯粹**：预设目录从 5 个冗余子目录精简为 3 个场景明确的独立单元，完美契合 Pi 极简、轻快的产品灵魂。
